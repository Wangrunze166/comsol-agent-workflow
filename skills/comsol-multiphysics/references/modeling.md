# 输入与建模

填写 JSON 时读项目根目录的 `docs/case-format.md`；新建或修改模型时复制 `templates/model-configuration.template.md` 记录证据。相对路径以原始工作流仓库为基准。

## 证据分层

记录用户提供的模型、原始数据、CAD、材料手册、官方案例说明与 Java 导出；每项写明来源、用途和版本。报告中的近似数值不能自动成为严苛的数值复现阈值。既有报告的成功记录只属于其当时的模型与执行器。

案例配置应覆盖下表。缺失值保持未知，不使用看似合理的默认值填补真实工程信息。

| 项目 | 必须可复核的内容 |
|---|---|
| 目标与范围 | 决策问题、研究类型、关键输出、允许误差及不在范围内的现象 |
| 几何 | 维度、长度单位、尺寸/CAD 版本、域与边界含义、对称与薄层简化 |
| 参数 | 数值、单位、维度、来源、允许范围；绝对温度与温差分开 |
| 材料 | 属性数值或函数、单位、温压适用范围、各向异性、指定域 |
| 物理场 | 接口与特征标签、未知量、方程/物性关系、域与边界选择 |
| 耦合 | 传递量、方向、单位、时间尺度、求解次序及冻结变量 |
| 初始/边界条件 | 位置、类型、表达式、参考压力/温度、电势或约束基准 |
| 网格 | 特征尺寸、薄隙/边界层分辨率、质量与单元数、命名选择 |
| 求解器 | 研究步骤、求解序列标签、各步骤激活物理场、容差、缩放、初始化 |
| 输出与验证 | 数据集、表达式、单位、采样点、守恒/解析/试验/参考解标准 |

## 本 MVP 的配置边界

执行器接收已经在 COMSOL 6.3 中完成配置并审阅的 MPH，设置清单中的参数覆盖，运行指定求解序列，导出指定全局量。现有几何、材料、边界、网格和求解器是输入模型的一部分。

新模型或配置变更按以下交接实现：

1. 在 6.3 中建立或修改模型，使用命名选择固定语义，核对几何重建后的域/边界。
2. 导出 Model File for Java，保留修改前后 MPH 和配置摘要。由 6.3 导出的 feature 类型、属性名与标签作为 API 适配依据。
3. 对几何、材料、物理场、耦合、网格、求解器逐项审阅；以新 MPH 替换案例输入，记录相关依赖。
4. 对最终输入生成新的计划与审批，再使用执行器复算。

MVP 不将任意自然语言直接翻译为所有 COMSOL 物理接口。Java builder、LiveLink、远程服务等可作为后续适配器；它们必须满足同样的输入清单、配置证据与审批契约。未经验证的 feature 字符串不进入可执行模型。

## 一致性检查

静态检查针对已声明参数的单位和维度、有限数值、范围与指定关系。完整 COMSOL 表达式、材料函数和几何拓扑仍需在 COMSOL 内核中检查；单位检查通过不能证明模型表达式全部正确。

工程审阅至少检查：

- 长度、时间、压力、功率、电流与温度单位一致；温差使用 K，绝对摄氏温度涉及偏移换算。
- 热源的 W 与 W/m³、面热流的 W/m²、总力与应力、质量流率与速度分开。
- 材料属性与温度范围吻合，导热率/密度/热容等应为正，控制器增益可按定义为负。
- 每个守恒方程有充分边界条件和基准，约束没有遗漏或重复。
- 耦合量的接收域和方向明确；冻结流场、单向耦合、稳态近似分别写入假设。
- 参数扫描或几何变化后重新核对选择、网格及求解器适用性。

## 今日参考案例的关键含义

参考对象是官方 Application ID 102421：集总热电模块与 PID 控制。已恢复的配置使用三维空气域、散热器、器件及接触层，集总热网络与温控方程配合传热计算。微分项为零，实际为 PI 控制。先求稳态流场，随后冻结流场进行稳态扫描或瞬态热学/控制计算。

因此，此案例不证明全瞬态双向流热耦合，也不证明任意电热流固耦合接口均已自动化。每个新场景仍应明确方程、耦合方向和验证要求。
