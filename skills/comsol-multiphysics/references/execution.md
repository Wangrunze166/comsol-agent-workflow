# 执行与诊断

## 通用 Skill 与专属执行器

通用 Skill 管理证据、工程假设、审批、验证标准和交付。COMSOL 6.3 执行器负责读取已审阅模型、生成 Java 驱动、编译、运行求解序列和输出记录。后续版本应另做适配验证；不能只修改版本字符串就宣称兼容。

真实运行前核对本机 COMSOL 安装、补丁版本、所需模块与有效许可。安装文件存在不等于许可证可用。MVP 不自动安装 COMSOL，不修改许可证，也不接管已有交互式会话。

## 两个人工检查点

1. **工程假设确认：** 用户查看最终案例、来源、简化、单位、边界解释、耦合策略和验证阈值，确认模型表达的是目标问题。
2. **实际求解审批：** 用户查看当前输入与执行器哈希绑定的计划、求解序列、参数覆盖、输出位置、资源与时间上限，再批准实际计算。

生成审批模板只是在准备审批，不代表同意。智能体只能记录用户对该具体计划的明确决定。任一受绑定的输入或执行计划变化后，旧审批失效。审批文件是本地审计记录，不能当作密码学身份认证或多用户权限系统。

## 求解配置审阅

已有模型的求解序列必须覆盖预期步骤。先流场后传热的案例应检查前置流场是否实际重算、后续步骤是否使用正确解；仅调用最后一个 solver 可能遗漏依赖。记录耦合/分离求解策略、变量缩放、线性求解器、相对容差、时间步约束、初值和延续方式。

参数覆盖可能影响几何、网格、材料和求解器；当前执行器的能力边界以实现说明为准。涉及需要重新构建的配置时，先制备并审阅新的 MPH，不能假定一次参数写入会自动更新整个模型。

## 收敛诊断

同时查看返回码、完成标记、实际终止时间/扫描点数和原始日志。日志中的时间步失败或非线性重试可能已被后续缩步恢复，不能单凭词语 “failed” 判整个计算失败。

| 现象 | 优先检查 | 审阅后的候选处理 |
|---|---|---|
| 奇异矩阵/未定义变量 | 约束基准、材料域、空选择、表达式作用域 | 修正缺失物理定义与选择 |
| 非线性迭代不收敛 | 初值、变量缩放、耦合强度、物性不连续 | 参数延续、合理平滑、分离/全耦合策略比较 |
| 瞬态步长持续缩小 | 事件、激励跃变、刚性、控制限幅 | 检查事件解析和输出要求，比较时间步/容差 |
| 内存不足 | 单元/自由度、线性求解器、并行设置 | 经批准比较网格或求解器；保留精度标准 |
| 计算完成但结果异常 | 单位、符号、数据集、选择、耦合方向 | 先修模型解释，再考虑调整数值方法 |

诊断建议是待评估的假设。禁止通过放宽验证阈值掩盖失败，也不在未批准情况下反复重算。模型修改后生成新的计划与审批。

执行超时或中断后，保留已有日志、状态和可能的部分结果，并标为未完成；恢复计算须核对剩余进程及输出完整性。
