# 开源与定制开发路径

## 开源边界

本 MVP 建议用 MIT 发布原创工作流代码、Skill、模板和合成演示，降低工程团队试用与集成成本。[MIT 正文](../LICENSE) 允许使用、修改和再分发，要求保留版权及许可声明；标准文本可对照 [Open Source Initiative](https://opensource.org/license/mit)。

该许可只覆盖有权授权的仓库内容。COMSOL 软件、模块、商标、官方模型、客户 CAD 和材料数据不自动纳入 MIT。发布前按来源逐项核验可分发范围；客户的使用与算力部署也需符合其 [COMSOL 6.3 许可条款](https://doc.comsol.com/6.3/doc/com.comsol.help.comsol/comsol_la_license.04.1.html)。若以后选择双许可证或重新许可，需先核对已有贡献的权利与协议。这是项目方案，具体合同与许可安排应另行审核。

## 第一批可收费服务

| 服务 | 可验收交付 | 与开源的关系 |
|---|---|---|
| 客户模型接入 | 证据清单、参数表、选择/标签映射、可复算案例、运行记录 | 复用开源执行器，收取接入与验证工作费用 |
| 领域建模模板 | 一个明确物理领域的几何/材料/耦合 builder 与代表性基准 | 针对性工程知识与测试形成服务价值 |
| 求解稳定性改进 | 可复核的问题定位、配置对照、精度与性能结果 | 按证据交付改进，不保证所有模型必然收敛 |
| 团队工作流部署 | 私有代码库、审批留痕、报告格式、客户环境适配 | 软件开放，部署与持续维护收费 |
| 验证与可复现交付 | 网格/时间/参数敏感性研究、参考解比较、适用范围报告 | 计算预算与验证范围单独约定 |

优先从“一个客户、一个模型族、一个明确验收指标”开始。首个产品范围可选热电/传热控制模型复现与参数化报告，避免把全行业任意多物理场自动建模作为首版销售承诺。

## 定制合同中写清的内容

- 客户提供的模型、材料、CAD 与实验数据是否完整、是否有权使用。
- 所需 COMSOL 版本/模块、运行环境、许可责任与计算资源预算。
- 工况范围、输出指标、验收阈值、变更次数和人工审阅职责。
- 原始模型、客户数据、新增 builder、通用执行器与报告的权属及交付范围。
- 求解失败、基准不足或模型本身不成立时的诊断交付方式。
- 后续版本适配、维护期限、响应方式与独立报价边界。

报价以实际模型复杂度、配置变更、验证次数和支持范围估算；首版不预设缺乏依据的统一价格。

## 获客与可信展示

GitHub 仓库公开代码、架构、可复现离线演示与真实验证边界。围绕已验证案例发布技术说明，展示输入如何变为可审核计划、审批如何绑定计算、错误如何被发现、结果如何被验证。

把意向用户引导到明确的接入信息表：物理场、模型版本、输入来源、工况数、输出和验收要求。先评估代表性案例，再决定是否承诺完整自动化。未经客户明确授权，私有模型、日志和结果不进入公开演示。
